# Native-to-Universal Mapping

## Required Phase 1.2 contract outputs

### asset_master.csv
Create one stable Universal record for each metal and each investable vehicle exported. Native metal names and tickers must map through a maintained crosswalk; they must not be used as the Universal primary key without namespacing.

### forecasts.csv
Primary source: `latest_metal_forecasts.csv`. Map horizon, expected return, lower/upper bounds, volatility, downside probability, model agreement, run ID, and as-of metadata. Regime probabilities and model components remain evidence/detail files unless the Universal schema has extension fields.

### recommendations.csv
Primary source: `latest_metal_opportunity_rankings.csv`, supplemented by latest recommendation history/change explanations and vehicle recommendations where required. Preserve native rationale and confidence; do not reinterpret action labels in the adapter.

### risk_metrics.csv
Use current portfolio risk, stress, downside probability, forecast volatility, and related latest views. This requires a deliberate Phase 1.2 query/export because the current v8 CSV set does not expose the full native risk surface.

### portfolio_positions.csv
Source from `latest_portfolio_positions`, plus targets/actions when needed. The current v8 exporter does not write this file, so Phase 1.2 must add a read-only native export or adapter query.

### platform_status.csv
Source from `latest_platform_health_score` and `latest_data_freshness_details`. Include current release, run status, freshness, validation status, and completeness.

### export_manifest.csv
Generated by the adapter. Include all files, checksums, row counts, source run IDs, source release, timestamps, contract version, and validation results.

## Optional/supporting outputs

Model components, regime probabilities, recommendation changes, and committee report metadata should remain packaged as auditable supporting files. They are valuable, but not all are required as first-class Universal tables.

## Mapping gaps to resolve

- Stable `asset_id` and vehicle crosswalk
- Authoritative `as_of_date` per output
- Native action-to-Universal recommendation enum mapping
- Currency and return-unit normalization
- Portfolio/account identifiers
- Full risk and position export coverage
- Nullability and confidence-scale reconciliation
